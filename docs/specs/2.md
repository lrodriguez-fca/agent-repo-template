# Spec: #2 Create Pomodoro app

Status: Approved   Owner: lrodriguez-fca   Issue: https://github.com/lrodriguez-fca/agent-repo-template/issues/2

## Context
A Pomodoro timer that helps users alternate between focused work and breaks. Users start, pause and reset the timer, configure durations, see the current session type, and are notified when the timer finishes. Settings persist between visits. The app must be keyboard-accessible and work well on mobile and desktop.

Session types: **Focus**, **Short break**, **Long break**. "Timer" means the countdown for the current session.

## Requirements (EARS)

### Timer control
- REQ-001: The Pomodoro app shall display the remaining time of the current session in MM:SS format.
- REQ-002: When the user activates Start while the timer is idle or paused, the app shall begin counting down from the remaining time.
- REQ-003: When the user activates Pause while the timer is running, the app shall stop the countdown and retain the remaining time.
- REQ-004: When the user activates Reset, the app shall stop the countdown and restore the remaining time to the full configured duration of the current session type.
- REQ-005: While the timer is running, the app shall keep the remaining time accurate to wall-clock time, including after the tab is backgrounded or throttled.
- REQ-006: While the timer is running, the app shall not offer Start; while idle or paused, the app shall not offer Pause.

### Sessions
- REQ-007: The app shall display the current session type at all times.
- REQ-008: When a Focus session reaches zero, the app shall switch to a Short break, or to a Long break after every N completed Focus sessions (N configurable).
- REQ-009: When a break session reaches zero, the app shall switch to a Focus session.
- REQ-010: When a session ends, the app shall leave the next session ready and not start it until the user activates Start.
- REQ-011: The app shall display the number of Focus sessions completed in the current cycle.

### Configuration
- REQ-012: The app shall let the user configure the durations of Focus, Short break and Long break in whole minutes, and the Focus count N before a Long break.
- REQ-013: If the user enters a value outside the allowed range (see Open questions) or a non-integer, then the app shall reject it, show an error message associated with the field, and keep the previous valid value.
- REQ-014: When the user changes a duration while the timer is idle, the app shall apply it to the matching session type immediately.
- REQ-015: When the user changes the duration of the current session type while the timer is running or paused, the app shall apply it from the next session (the current countdown is not altered).
- REQ-016: When the user saves valid settings, the app shall persist them in browser local storage.
- REQ-017: When the app loads, the app shall restore persisted settings.
- REQ-018: If persisted settings are missing, corrupt, or invalid, or storage is unavailable, then the app shall use the defaults and continue to function.

### Notifications
- REQ-019: When a session reaches zero, the app shall show an in-page message announcing that the session ended and naming the next session.
- REQ-020: Where the browser supports the Notification API and permission is granted, when a session reaches zero, the app shall also show a system notification.
- REQ-021: When the user first enables notifications, the app shall request notification permission; the app shall not request it on page load.
- REQ-022: If notification permission is denied or unsupported, then the app shall rely on the in-page message and continue to function.
- REQ-023: Where sound is enabled, when a session reaches zero, the app shall play a short alert sound.

### Accessibility and responsiveness
- REQ-024: The app shall make every control (Start, Pause, Reset, settings, notification toggle) operable by keyboard alone, with a visible focus indicator and logical tab order.
- REQ-025: When the session type or the end-of-session message changes, the app shall announce it to assistive technology via a polite live region; the per-second countdown shall not be announced continuously.
- REQ-026: The app shall provide an accessible name for every control and input and shall not convey session type by color alone.
- REQ-027: The app shall present a usable layout, with no horizontal scrolling and touch targets of at least 44×44 CSS px, from 320 px viewport width to desktop.
- REQ-028: While the timer is running, the document title shall show the remaining time and session type.

## Dependencies
- Browser APIs: `localStorage`, Notification API (optional), Web Audio/HTMLAudioElement (optional).
- Stack: React + React Router (client-only SPA). Build/test tooling is still TODO in AGENTS.md and must be chosen during implementation.
- Standards: `.github/skills/accessibility-standards` (WCAG 2.2 AA), `security-standards`, `observability-standards`.

## Open questions (agent: ask, don't guess)
All resolved by the owner:
1. Stack: React with React Router as a client-only SPA (library/data mode, no SSR, no backend).
2. Defaults: 25 / 5 / 15 minutes; Long break after 4 Focus sessions.
3. Allowed ranges: 1-120 min per duration; N of 1-10.
4. No auto-start of the next session (REQ-010).
5. A running timer does not survive a page reload/close; only settings persist.
6. Sound is optional, default off (REQ-023).
7. Browsers: latest 2 versions of Chrome, Firefox, Safari and Edge, plus iOS Safari and Android Chrome. English only; no i18n.
8. Reset affects only the current countdown, not the completed-Focus count.
9. No skip-to-next-session control (out of scope).

- AT-002 (REQ-002, 006): Click Start; with fake timers advance 3 s; display shows `24:57`; Start is not offered, Pause is.

- AT-004 (REQ-004): Reset while running and while paused; display `25:00` and timer idle.
- AT-005 (REQ-005): Simulate a clock jump of 60 s with no ticks; the next tick shows time reduced by 60 s.
- AT-006 (REQ-007, 011): Current session label is present in each state; the completed counter increments after each Focus session.
- AT-007 (REQ-008): Complete 4 Focus sessions; the 4th transitions to Long break, earlier ones to Short break; with N=2 the 2nd does.
- AT-008 (REQ-009, 010): Break ends; next is Focus, idle, not counting down until Start.
- AT-009 (REQ-012, 14): Change the Focus duration to 30 while idle; display shows `30:00`.
- AT-010 (REQ-013): Enter `0`, `-5`, `abc`, `2.5`, and an over-range value; each shows an associated error and leaves settings unchanged.
- AT-011 (REQ-015): Change the Focus duration while running; the current countdown is unchanged and the new value applies to the next Focus session.
- AT-012 (REQ-016, 017): Save settings, reload; the same values appear.
- AT-013 (REQ-018): Seed local storage with invalid JSON, out-of-range values, and a throwing storage; the app loads with defaults and no error.
- AT-014 (REQ-019, 025): At zero, the message names the next session and appears in a polite live region; the live region is not updated every second.
- AT-015 (REQ-020, 21, 22): Mock Notification: granted → a notification fires at zero; no permission request on load; denied/unsupported → no throw and the in-page message still appears.
- AT-016 (REQ-023): With sound on, the audio plays once at zero; with it off, nothing plays.
- AT-017 (REQ-024, 026): Keyboard-only run through all flows; focus visible; automated axe check reports no WCAG 2.2 AA violations; session type is available as text.
- AT-018 (REQ-027): At 320 px and 1280 px viewports there is no horizontal scroll; interactive targets ≥ 44×44 px.
- AT-019 (REQ-028): While running, `document.title` contains the time and session type.

## Non-functional (a11y, performance budget, security, observability, privacy)
- **Accessibility:** WCAG 2.2 AA; contrast ≥ 4.5:1; respects `prefers-reduced-motion`; automated axe in CI plus a manual keyboard and screen-reader pass.
- **Performance:** Initial JS ≤ 100 KB gzip (proposed); interactive in < 2 s on a mid-range mobile on 4G; the timer tick must not cause layout thrash.
- **Security:** No secrets; no third-party scripts; treat stored settings as untrusted input and validate on read; render values via text nodes, not raw HTML; set a restrictive CSP.
- **Privacy:** Only settings are stored locally; no analytics or network calls, so no consent banner is needed.
- **Observability:** Client-only app, so no server logs; surface storage and notification failures via `console.warn` in development only.

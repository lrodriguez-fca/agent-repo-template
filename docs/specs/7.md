# Spec: #7 Dark mode

Status: Draft   Owner: lrodriguez-fca   Issue: https://github.com/lrodriguez-fca/agent-repo-template/issues/7

## Context
Issue body: "The app should have light, dark, and system modes for the UI."

Extends the Pomodoro app (`docs/specs/2.md`). The user can choose a theme **mode**: **Light**, **Dark**, or **System**. The applied **theme** (light or dark) is derived from the mode; System follows the operating system's `prefers-color-scheme`.

## Requirements (EARS)

### Mode selection
- REQ-001: The app shall offer three theme modes: Light, Dark and System.
- REQ-002: When the user selects Light or Dark, the app shall apply that theme immediately, without reload.
- REQ-003: While the mode is System, the app shall apply the theme matching the operating system's `prefers-color-scheme`.
- REQ-004: While the mode is System, when the operating system color scheme changes, the app shall update the applied theme without reload.
- REQ-005: The app shall display the currently selected mode at all times.

### Persistence
- REQ-006: When the user selects a mode, the app shall persist it in browser local storage under a key separate from the timer settings.
- REQ-007: When the app loads, the app shall restore the persisted mode.
- REQ-008: If the persisted mode is missing, invalid, or storage is unavailable, then the app shall use System mode and continue to function.
- REQ-009: The app shall apply the resolved theme before first paint, so that no flash of the wrong theme is shown on load.

### Scope
- REQ-010: The app shall apply the theme to every UI element, including controls, inputs, error messages, focus indicators and the in-page end-of-session message.
- REQ-011: The theme change shall not alter timer state, current session, or settings values.

### Browser hints
- REQ-015: When the applied theme changes, the app shall update the CSS `color-scheme` and `<meta name="theme-color">` to match it.

### Accessibility
- REQ-012: The app shall present the mode control as a radio group, placed next to the timer settings, and shall make it operable by keyboard alone, with an accessible name, a visible focus indicator, and a touch target of at least 44×44 CSS px.
- REQ-013: In both themes, the app shall meet WCAG 2.2 AA contrast (text ≥ 4.5:1, UI components and focus indicators ≥ 3:1) and shall not convey state by color alone.
- REQ-014: When the user changes the mode, the app shall expose the selected mode to assistive technology through the control's state (e.g. selected/checked) without moving focus.

## Dependencies
- Spec `docs/specs/2.md` (settings persistence REQ-016–018, accessibility REQ-024–027).
- Browser APIs: `matchMedia('(prefers-color-scheme: dark)')`, `localStorage`.
- Standards: `.github/skills/accessibility-standards`, `security-standards`.

## Open questions (agent: ask, don't guess)

3. Persisted in local storage under a separate key from the timer settings (REQ-006).

## Acceptance tests (one or more per REQ)
- AT-001 (REQ-001, 005): Render; Light, Dark and System options are present and the selected one is indicated.
- AT-002 (REQ-002, 011): Select Dark while the timer is running; the dark theme applies, with no reload, and the countdown and settings are unchanged. Repeat for Light.
- AT-003 (REQ-003): With `matchMedia` mocked to dark and mode System, the dark theme applies; mocked light gives the light theme.
- AT-004 (REQ-004): In System mode, dispatch a `matchMedia` change event; the applied theme updates.
- AT-005 (REQ-006, 007): Select Dark, reload; Dark is selected and applied.
- AT-006 (REQ-008): Seed storage with invalid value, missing value, and a throwing storage; the app loads in System mode with no error.
- AT-007 (REQ-009): Playwright: with Dark persisted, the first rendered frame already uses the dark theme (no light-to-dark change).
- AT-008 (REQ-010): Playwright: in both themes, screenshots or computed styles show no element retaining the other theme's colors, including error and end-of-session message states.
- AT-009 (REQ-012, 014): Keyboard-only selection of each mode; focus visible, accessible name present, selected state exposed, focus not moved; target ≥ 44×44 px.
- AT-010 (REQ-013): axe reports no WCAG 2.2 AA violations (including contrast) in light and dark themes, at 320 px and 1280 px.
- AT-011 (REQ-015): Switch between themes; `color-scheme` and the `theme-color` meta content change to match.

## Non-functional (a11y, performance budget, security, observability, privacy)
- **Accessibility:** WCAG 2.2 AA in both themes; respects `prefers-reduced-motion` (no animated theme transition when set).
- **Performance:** No added runtime dependency; no layout shift on theme change; counts toward the existing initial JS budget of ≤ 100 KB gzip.
- **Security:** Treat the stored mode as untrusted input and validate against the three allowed values; any pre-paint inline script must be compatible with the restrictive CSP (use a hash/nonce or an external file).
- **Privacy:** Only the mode is stored locally; no network calls.
- **Observability:** Surface storage failures via `console.warn` in development only.
